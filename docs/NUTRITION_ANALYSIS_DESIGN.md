# 女子長距離選手向け 食事分析AI ロジック定義書

本ドキュメントは、正確な定量（g単位）ではなく、**食品群レベルでの半定量評価（Semi-quantitative assessment by food groups）** を行い、統計解析（ベイズ階層モデル等）に使用可能な順序尺度データ（Ordinal Data）を生成するためのAIロジックを定義します。

## 1. 分析の基本方針
*   **目的**: 鉄欠乏性貧血およびEnergy Availability (EA) 低下の**リスク因子の検出**。
*   **入力**: 食事の写真 または テキスト記述（メニュー名・量）。
*   **出力**: 栄養素量（mg/kcal）ではなく、**食品群別摂取レベルスコア (0〜3)**。
*   **統計的妥当性**: 
    *   連続値としての扱いは避け、順序変数（Ordered Categorical）として定義する。
    *   日次変動のノイズを許容し、週単位・月単位のトレンド解析に耐えうる構造とする。

## 1.5. 入力データ仕様 (Input Data Specification)

AIは以下の情報を入力として受け取り、分析を実行します。

| 項目 | 必須 | 説明 | 備考 |
| :--- | :--- | :--- | :--- |
| **食事画像** | 必須 | **1食につき1〜3枚** | 全体が写ったもの＋アップなど。画質はスマホ撮影レベルを想定。 |
| **補足テキスト** | 任意 | 食事の状況や特記事項 | 例:「朝食」「練習後」「外食」「食欲なし」「残した」など。 |

※ 画像がない場合でもテキストのみでの簡易分析（信頼度レベルB/C）を可能としますが、原則は画像入力を推奨します。

## 2. 画像認識・推論ロジック (Step 1)

AIはまず画像から以下の情報を抽出します。**カロリーやグラム数などの数値推定は行わず**、カテゴリと概算量のみを判定します。

### 2.1. 食品群分類 (Food Groups)
以下の8カテゴリに分類・検出します。

1.  **主食**: 米、パン、麺類、シリアル
2.  **肉**: 赤身肉（牛・豚・血合い魚）、加工肉（ハム・ソーセージ）、鶏肉
3.  **魚介**: 白身魚、甲殻類、貝類（血合い魚は「肉」カテゴリの赤身相当として扱うか、属性で区別する）
4.  **卵**: 鶏卵、うずら
5.  **大豆・豆製品**: 納豆、豆腐、煮豆、豆乳
6.  **野菜**: 緑黄色野菜（ほうれん草、ブロッコリー等）、淡色野菜（キャベツ、レタス等）、きのこ、海藻
7.  **乳製品**: 牛乳、ヨーグルト、チーズ
8.  **その他**: 果物、菓子、嗜好飲料など

### 2.2. 量の推定 (Portion Estimation)
各検出アイテムに対し、以下の3段階で評価します。

*   **少ない (Small)**: 明らかに1人前より少ない、一口サイズ
*   **適量 (Medium)**: 一般的な1人前相当
*   **多い (Large)**: 山盛り、大盛り、複数個

---

## 3. 評価項目とスコアリング基準 (Step 2: Scoring)

各項目は原則として `0` (None/Low) 〜 `3` (High/Optimal) の整数値で評価します。

### A. 鉄分供給源 (Iron Sources)

#### 1. ヘム鉄スコア (`hem_iron_score`)
赤身肉、魚（血合い部分）など、吸収率の高い鉄分の評価。
*   `0`: なし
*   `1`: 少量 (例: ひき肉少量、ハム数枚)
*   `2`: 中等量 (例: 1人前の魚、豚肉炒め)
*   `3`: 多量・高密度 (例: 牛ステーキ、レバー、カツオのたたき)

#### 2. 非ヘム鉄スコア (`non_hem_iron_score`)
大豆製品、緑黄色野菜、卵、海藻など。
*   `0`: なし
*   `1`: 副菜1品程度 (例: 冷奴のみ)
*   `2`: 複数品目あり (例: 納豆＋小松菜お浸し)
*   `3`: 充実している (例: 具沢山味噌汁＋副菜2品以上)

### B. 吸収調節因子 (Absorption Modulators)

#### 3. ビタミンC・酸スコア (`absorption_enhancer_score`)
鉄吸収を促進する食品群（果物、生野菜、酢・梅干し等）。
*   `0`: なし
*   `1`: 少量 (例: 付け合わせのキャベツ、ドレッシング)
*   `2`: 十分あり (例: 果物1個、サラダボウル、100%ジュース)

#### 4. 吸収阻害フラグ (`inhibitor_flag`)
食事中・食直後のタンニン（コーヒー、紅茶、緑茶）摂取。
*   `0`: なし (水、麦茶、ほうじ茶など)
*   `1`: あり (食事と一緒に緑茶・コーヒー等)
*   ※ 統計解析時は負の係数を想定したダミー変数として扱う。

### C. エネルギー可用性プロキシ (Energy Availability Proxy)

#### 5. 糖質可用性スコア (`carb_intake_score`)
練習によるグリコーゲン枯渇を補う主食量。
*   `0`: 不足 (主食抜き、極端に少ない)
*   `1`: やや少なめ (茶碗半分、パン1個)
*   `2`: 標準 (どんぶり飯、パスタ1人前)
*   `3`: 高炭水化物 (大盛り、主食重ね食べ ※リカバリー食)

---

## 4. 研究用スコア算出 (Step 3: Research Grading)

Step 1, 2 の結果を統合し、統計解析の目的変数に対する説明変数として用いるための「充足度グレード」を算出します。
**※ サプリメントの摂取はスコア計算に含めず、フラグ記録のみに留めます（食事からの摂取能力を評価するため）。**

### 4.1. 鉄関連食品スコア (`iron_intake_grade`)
赤身肉・魚・卵・大豆の有無と量から総合評価 (-2 ~ +2)
*   `+2` (十分): ヘム鉄源(Large/Medium) ＋ 非ヘム鉄源 が揃っている
*   `+1` (まずまず): ヘム鉄源(Small) または 非ヘム鉄源が豊富
*   ` 0` (普通): 一般的なメニュー
*   `-1` (不足): 鉄欠乏リスクあり（肉魚なし、など）
*   `-2` (ほぼ無し): 具なし麺のみ、パンのみ等

### 4.2. 炭水化物スコア (`carb_intake_grade`)
主食量・主食の有無から評価 (-2 ~ +2)
*   `+2` (十分): 大盛り、重ね食べ（リカバリー基準）
*   `+1` (適量): 標準的な1人前
*   ` 0` (普通・維持): やや少なめだが活動量に対し許容範囲
*   `-1` (不足): 明らかに不足（茶碗半分以下）
*   `-2` (欠乏): 主食抜き

### 4.3. エネルギーバランススコア (`energy_balance_grade`)
全体量・欠食・練習量のコンテキストを考慮 (-2 ~ +2)
*   `+2` (十分): 練習量に見合う十分な量
*   `+1` (適量): 標準的
*   ` 0` (均衡): プラマイゼロ推定
*   `-1` (不足): 練習後だが量が少ない、軽食のみ
*   `-2` (明らかに不足): 欠食、極端な制限

## 5. 保存データ形式 (Database Schema)

分析完了後、データベースには以下のフラットな形式で保存され、縦断解析等の二次利用に供されます。
※ JSON構造はアプリケーション内（中間データ）で使用し、永続化はこのスキーマに従います。

| カラム名 | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `athlete_id` | string | 選手ID | "STU_001" |
| `date` | date | 日付 | "2024-04-10" |
| `meal_type` | string | 食事区分 | "dinner" |
| `iron_food_score` | int | 鉄関連食品スコア **(-2 ~ +2)** | 2 |
| `carbohydrate_score` | int | 炭水化物スコア **(-2 ~ +2)** | 1 |
| `energy_balance_score` | int | エネルギーバランススコア **(-2 ~ +2)** | 2 |
| `detected_food_groups` | text | 検出された食品群（テキスト化） | "肉(牛), 野菜(緑黄色)" |
| `notes` | text | 補足メモ（ユーザ入力 + AI付記） | "練習後, サプリあり" |

## 6. 縦断解析・集約戦略 (Longitudinal Analysis Strategy)

本システムで生成されたデータは、以下の戦略で加工され、ベイズ階層モデルへ投入されます。

### 6.1. データの結合と集約 (Data Aggregation)
`athlete_id` と `date` をキーとして、異なる頻度のデータを統合します。

1.  **日次レベル (Daily Integration)**
    *   **食事スコア**: 1日分のスコア合計または平均を算出 (Daily Iron Grade, Daily Energy Grade)
    *   **日次ログ**: RPE, 睡眠時間, 疲労度, 走行距離を結合
2.  **期間集約 (Rolling Windows)**
    *   採血日(`date_t`)を基準点とし、**過去7日 / 14日 / 28日** の期間平均を算出します。
    *   指標例: `avg_iron_grade_28d`, `avg_rpe_7d`

### 6.2. 個人内標準化 (Intra-individual Standardization)
個人のベースラインからの変動（乖離）を評価するため、モデル投入前に以下の処理を想定します。

*   **Centering**: $X'_{it} = X_{it} - \bar{X}_{i}$ （個人の全期間平均 $\bar{X}_{i}$ からの偏差）
*   **Purpose**: 「普段より食事が摂れているか/不足しているか」が、個人のフェリチン・Hb変動にどう影響するかを推定します。

### 6.3. 解析モデルイメージ (Bayesian Hierarchical Model)

```r
# R / Stan pseudo-code
model {
  # 目的変数: Hb (Hemoglobin) or Ferritin
  Hb[i, t] ~ Normal(mu[i, t], sigma)

  mu[i, t] = alpha[i] +  # Random Intercept (ベースラインの個人差)
             beta1 * (IronGrade_28d[i, t] - mean_Iron[i]) +   # 鉄摂取の個人内偏差
             beta2 * (EnergyGrade_28d[i, t] - mean_Energy[i]) + # エネルギーの個人内偏差
             beta3 * (RPE_7d[i, t] - mean_RPE[i]) +           # 負荷の個人内偏差 (HR Drift等)
             beta4 * Sleep_Quality[i, t]                      # 睡眠
}
```
この解析を可能にするため、Rawデータ（Step 4）は**日次・食事ごとの粒度**を維持して保存されます。
